# Why each hook, rule and agent exists

Read this before removing, loosening or reworking a hook, a rule of `CLAUDE.core.md` or an agent: the code says what
it does, this file says what problem it answered. Recovered from CHANGELOG.md, commit messages and the `## Why` of the
issues the commits close (2026-11-10, HEAD 54b2fb2); nothing filled by reasoning.

- `not recorded`: no source states it. Such a row is the owner's to explain or retire, never a reason to guess.
- `CODE-COMMENT`: only a comment in the script states it, a weaker source.
- Git history starts at 2.0.0 (`3c88990`, 2026-10-15): reasons for 1.x behavior are mostly not in this repo.
- Sources: `CL:<line>` or `CL x.y.z` = CHANGELOG.md; `<hash>` = commit message; `#n` = issue on korn9537/ai-kit;
  `SPEC-TOKEN`/`spec` = docs/superpowers/specs/2026-10-25-token-management-design.md; `SC` = docs/shared-checkout.md;
  `RM` = README.md. Line numbers in `CL:`, `RM:` and CLAUDE.core.md are as of 54b2fb2, before this file's commit.

A new hook, rule or agent adds its row in the same commit, with the measured or observed problem and, where one
exists, the figure in `usage.mjs digest` that would show it is no longer needed (`retire when`).
`scripts/why.test.mjs` fails when a script wired in `hooks/hooks.json` or a file in `agents/` has no row.
